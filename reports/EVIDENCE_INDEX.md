# Evidence index

Every claim this project makes, the artefact that backs it, and the command that
regenerates that artefact from source.

**Why an index rather than a list of results.** A number in a report is only
evidence if someone can reproduce it. `reports/intent_classifier_comparison.csv`
and `reports/intent_classifier_report.md` were last written on **2026-07-23** by a
generator that no longer existed, while `data/DATASET.md` cited the report as the
five-model evidence — so anyone quoting it was quoting 0.9417 from a corpus that
had since been replaced twice. Nothing in the repository rewrote those files, and
nothing detected that. The regeneration column is the fix for that class of
staleness; `tests/test_evidence_index.py` checks that every path named below
exists.

Paths are repository-relative. Run every command from the repository root with
`py -3.12` (see `handoff.md` §1 — the system Python installer on this machine is
broken and the MSIX interpreter is the one that works).

---

## How to regenerate everything at once

```bash
py -3.12 -m reports.generate_all_evidence
```

Individual generators are listed per component below. Two artefacts are *not*
regenerated by that script and are noted where they appear: the HTTP cassettes
(re-recording is a deliberate act, not a routine one) and the vendored UI assets.
